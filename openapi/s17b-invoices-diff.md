# S17b invoice batch contract

`openapi/ema.v1.json` and `openapi/s16-diff.md` are generated by
`uv run python scripts/generate_openapi_s16.py`.

## New operations

- `POST /jobs/{job_id}/invoices/files` accepts multipart `files` and optional
  `replace=invoices/NNNN`. It returns `InvoiceUpload {added, rejected}`; each
  accepted PDF has a numbered slot, the sanitized original file name, and SHA.
  Invalid type and oversize are per-file rejections. A whole-request problem uses
  `wrong_job_type` (400), `invalid_slot` (400), `job_missing` (404),
  `job_running` (409), or `validation_error` (422).
- `GET /jobs/{job_id}/invoices/page.png?slot=invoices/NNNN&page=N` returns
  `image/png` for a scoped PDF page. `page` is one-based; a missing page or slot
  is 404. Invalid slot and wrong job type are 400. Optional
  `crop=active_energy` centers and highlights the row's printed consumption;
  an unlocated value falls back to the full page. Invalid crop modes are 422.
- `GET /jobs/{job_id}/invoices/file?slot=invoices/NNNN` returns the scoped PDF
  as `application/pdf`. Missing files are 404; invalid slot and wrong job type
  are 400.

## Completed former provisional operations

- `GET /jobs/{job_id}/invoices` returns `InvoiceBatchView`: identity, invoice
  rows, missing months, failed/unsupported files, totals, year, and
  `read_ended_at`. Each row carries status, values, source page/snippet,
  issues, and optional outlier ratio and neighbour mean.
- `GET /jobs/{job_id}/invoices/identity` returns `InvoiceIdentity` with the
  proposed/confirmed client, printed-identity counts, POD filling summary,
  evidence IDs, memory, revision, and total file count.
- `POST /jobs/{job_id}/invoices/identity` accepts
  `InvoiceIdentityInput {client_id, on_revision, confirm}`. Confirmation requires
  a human session; stale revision and identity conflicts return 409.

## Changed schemas and behavior

- `SlotVersion` adds `slot_revision` for guarded `DELETE` requests; the versions
  read returns it from the same slot snapshot.
- `InvoiceIdentity` adds `name`, `reasons`, `pod_fill`, `memory`, `files_total`,
  and `client_cui`. `InvoiceBatchView` adds the table projection. These rows
  derive from the same invoice outcomes used by the CLI export.
- `InvoiceRow.consumption_kwh`, like the other decimal fields, travels as a
  JSON string so exact values survive the API boundary.
- Invoice outcomes retain source slot and SHA identifiers. Batch and identity
  views reject an outcome when its source no longer matches the active slot;
  older outcomes without identifiers need a new invoice read.
- Uploads keep the sanitized original PDF name as slot `origin` and in the
  extraction's `source_path`. POD filling matches the source SHA and slot so
  equal visible filenames cannot cross-fill evidence.
- Batch outliers use a ratio greater than or equal to 1.30 against the mean
  of available adjacent months. Unreadable or missing consumption stays
  missing; the view never synthesizes a value.
